Order picking math model

Strict order picking for one wave: each fulfilled order is one closed walk from a depot, then one picker is chosen for that whole order. This page is the model in order_picking/. Truck pads, axles, and pallet fill are a different model, written up in loadmax_model.html.

Display math uses MathJax. Open the file in a browser with network access so the formulas render. The source of each display is LaTeX.

What it decides

One picker finishes one order before starting another. Storage locations are dedicated: each line names one fixed slot.

Phase 1For each order, a closed walk from the depot you pass in, through that order’s distinct slots, and back.
Phase 2Which of those orders to release this wave, and which eligible picker does each one.
ScoreSum of priority weights of released orders, minus optional penalties. --staged-assignment reports that same release-weight sum.
Feasible by defaultReleasing nothing has objective \(0\). A tight shift shows up as orders left out. --require-must-ship is infeasible when those jobs cannot all fit.

A typical order has about 6 to 15 lines. The routing problem for one order is that small set of slots plus the depot. Phase 2 never rebuilds the walk. It treats each order’s duration \(\tau_o\) as a fixed number of minutes.

Travel time \(T_{ij}\)

Built once by Dijkstra on aisle centrelines. Phase 1 looks up \(T_{ij}\). It does not see \(x\) and \(y\).

Each aisle is one vertical centreline at a fixed \(x\), from \(y_{\min}\) to \(y_{\max}\). Each cross-aisle is one horizontal centreline at a fixed \(y\), from \(x_{\min}\) to \(x_{\max}\). A slot is a point on its aisle at that slot’s \(y\). Left and right racks at the same \(y\) share that point. There is no \(z\) coordinate. Extra time for an upper level is a larger retrieval time on the slot.

Junctions are the crossings where a cross-aisle \(y\) lies inside an aisle’s \(y\) range and the aisle’s \(x\) lies inside the cross-aisle’s \(x\) range. The depot is snapped to the nearest point on any centreline. The leftover off-centre distance is \(\sigma_d\), in minutes.

Edge length

On one centreline, consecutive nodes \(a\) and \(b\) at positions \(p_a\) and \(p_b\) get a directed walk time

\[ t(a,b) = \frac{|p_b - p_a|}{s} \]

\(s\) is --speed, distance units per minute. Default \(s = 1\), so the number equals distance. A blank one_way puts the edge in both directions. up keeps only increasing \(y\), down only decreasing \(y\), right only increasing \(x\), left only decreasing \(x\). A zero gap is a both-ways edge of length \(0\).

Shortest walk

From each public node (every depot and every slot) Dijkstra computes the least walk time along those edges. Junctions stay inside the graph. If any public pair has no directed walk, the builder stops and writes no table.

\[ \delta_i(i) = 0, \qquad \delta_i(j) = \min_{k:\,(k \to j)}\bigl(\delta_i(k) + t(k,j)\bigr) \]

The cell written for the picker adds the depot snap and the slot retrieval after Dijkstra:

\[ T_{ij} = \delta_i(j) + \sigma_i\,\mathbf{1}[i \text{ is a depot}] + \sigma_j\,\mathbf{1}[j \text{ is a depot}] + r_j\,\mathbf{1}[j \text{ is a slot}] \]

\(r_j\) is the slot’s own retrieval_time when that cell is filled, including a stored \(0\). A blank cell uses the global --retrieval-time, default \(0\). A walk that ends at a depot does not add retrieval. Item handling is \(p_o\), added later in phase 1. Leave \(r_j = 0\) when the order lines already carry pick_time, so those minutes are counted once.

Nearest depot label

With several depots in one graph, each slot is labeled by the shortest there-and-back walk. Retrieval sits on the slot, so it does not change the winner. Equal costs use the lexicographically smaller depot id.

\[ d^{\star}(\ell) = \operatorname*{arg\,min}_{d \in \mathcal{D}} \bigl(T_{d\ell} + T_{\ell d}\bigr) \]

Priority weight \(w_o\)

A linear weight, applied before phase 2. It is the coefficient of \(y_o\). It is not a rule that clears high-priority orders first.

The solver fills \(w_o\) in this order:

  1. A finite priority_weight already on the row is kept, when it is at least \(0\) and strictly below \(10^{6}\).
  2. Otherwise must_ship sets \(w_o = 10^{5}\).
  3. Otherwise \(w_o = u_o \cdot m_o\), urgency times the account-tier multiplier.
  4. After that, benchmark_mode replaces every weight with \(1\), including a stored weight and a must-ship weight.
\[ w_o = \begin{cases} 1 & \text{benchmark mode} \\ w_o^{\mathrm{given}} & \text{a finite explicit weight was stored} \\ 10^{5} & \text{must-ship, and no explicit weight} \\ u_o \, m_o & \text{otherwise} \end{cases} \]

Hours remaining \(h\) come from cutoff_time. A numeric cutoff with no clock means \(h\) is already hours remaining. A datetime cutoff uses \(h =\) cutoff minus now. One wave is \(H\) hours.

\[ u(h) = \begin{cases} 6 & h \lt 0 \\ 4 & 0 \le h \le H \\ 2 & H \lt h \le 2H \\ 1 & h \gt 2H \end{cases} \]

With no cutoff, urgency comes from hours already waited, \(q\). That path has no overdue band. \(q\) is wait_time, or now minus queued_since.

\[ u(q) = \begin{cases} 4 & q \ge 2H \\ 2 & H \le q \lt 2H \\ 1 & q \lt H \end{cases} \]

Default tier multipliers: key and A are \(2\); standard, B, and C are \(1\); a blank tier is \(1\). key_account true with a blank tier uses key. A boolean tier true uses key, false uses \(1\). Any other name is an error. Pass tier_multipliers to replace the whole table.

Due this wave and tier key: \(u = 4\), \(m = 2\), so \(w_o = 8\). Overdue and tier standard: \(w_o = 6 \times 1 = 6\). Must-ship with no stored weight: \(w_o = 100000\).

Phase 1 — route duration \(\tau_o\)

Distinct slots only. Two lines at the same location_id are one stop, and both pick_time values still add into \(p_o\). An order with no slots is an error. A missing pair \(T_{ij}\) is an error.

\[ p_o = \sum_{\text{lines } k \text{ of order } o} \mathrm{pick\_time}_k \]
\[ \tau_o = \text{(closed-walk minutes from } d \text{ through } L_o \text{)} + p_o \]

The depot is node \(0\) inside the tour. Every other node is one slot of \(L_o\).

One pick location

A single slot has no tour choice. The TSP object is not built. Its guard requires at least three nodes (the depot plus two slots), so this case is a direct lookup.

\[ \tau_o = T_{d\ell} + T_{\ell d} + p_o \qquad \text{route} = (d,\;\ell,\;d) \]
Sample layout, PACK_A at \((0,0)\), slot L1, speed \(1\), retrieval \(0\): \(T = 3\) each way, so \(\tau = 6\) when \(p_o = 0\).

Two or more slots — default tour

The default phase1_solver is heuristic. It walks the directed matrix. Start at the depot. The opening tour is nearest neighbor: from the current node, step to the closest unvisited slot, then close back to the depot.

\[ \text{next}(i) = \operatorname*{arg\,min}_{j \in U} T_{ij} \]

Then 2-opt. The move reverses the chain of stops from \(\mathrm{next}(i)\) through \(j\). Write that chain \(s_1,\ldots,s_m\) with \(s_1 = \mathrm{next}(i)\) and \(s_m = j\), and write \(d = \mathrm{next}(j)\). The directed gain is the removed walk minus the reversed walk:

\[ \Delta(i,j) = T_{i,s_1} + \sum_{t=1}^{m-1} T_{s_t,s_{t+1}} + T_{s_m,d} - \Bigl( T_{i,s_m} + \sum_{t=1}^{m-1} T_{s_{t+1},s_t} + T_{s_1,d} \Bigr) \]

A one-stop chain reverses nothing, so \(\Delta = 0\). When \(T\) is symmetric the edges along the chain cost the same in both directions and cancel, which leaves the four endpoint terms. A positive \(\Delta\) is the only swap that is applied. The default improver takes the best positive reversal among a neighbor list and repeats. The travel time reported to phase 2 is the directed walk \(\sum_i T_{i,\mathrm{next}(i)}\). If that walk is longer than the nearest-neighbor tour, the nearest-neighbor tour is kept. The neighbor list at a node keeps the \(k\) closest other nodes, with

\[ k = \max\bigl(1,\; \min(\lfloor \sqrt{n} \rfloor,\; n-1)\bigr) \]

\(n = 1 + |L_o|\) is the depot plus the slots. The closed-walk length that becomes the travel part of \(\tau_o\) is

\[ \sum_{i=0}^{n-1} T_{i,\,\mathrm{next}(i)} \]

The printed route lists the nodes from the depot and repeats the depot at the end, so the return leg is visible.

Sample layout, depot \((0,0)\), speed \(1\): \(T_{\mathrm{DEPOT},L1} = 3\), \(T_{L1,L2} = 13\), \(T_{L2,\mathrm{DEPOT}} = 10\). The walk \(\mathrm{DEPOT} \to L1 \to L2 \to \mathrm{DEPOT}\) has length \(3+13+10 = 26\). With \(p_o = 0\), \(\tau = 26\).

Exact tour — optional SCIP or HiGHS

phase1_solver scip or highs solves a directed tour on the same nodes. Every ordered pair \(i \neq j\) has its own binary \(x_{ij}\) and its own cost \(T_{ij}\). A one-way aisle therefore keeps the cheap direction and does not pay the blocked direction. The undirected city model in solve_scip and solve_highs is a separate demo. Warehouse orders do not call it.

\[ \min \sum_{i \neq j} T_{ij}\, x_{ij} \]
\[ \sum_{j \neq k} x_{kj} = 1 \qquad \sum_{i \neq k} x_{ik} = 1 \qquad \forall k \]
\[ x_{ij} \in \{0,1\} \]

Out-degree 1 and in-degree 1 make the chosen arcs a permutation: one or more directed cycles that cover every node. After each solve, every cycle \(S\) that is a proper subset of the nodes adds a cut, and the model is solved again until one cycle remains.

\[ \sum_{\substack{i \in S \\ j \notin S}} x_{ij} \ge 1 \qquad \text{for each directed cycle } S \subsetneq \{0,\ldots,n-1\},\; S \neq \emptyset \]

The cut says the tour must leave \(S\) at least once. The code adds one cut per cycle of the current solution. \(\tau_o\) is the directed length of the tour that is returned, \(\sum_i T_{i,\mathrm{next}(i)}\), plus \(p_o\).

Phase 2 — who may take an order

Equipment and per-order capacity are applied before the MILP. An ineligible pair has no variable \(x_{or}\). That is the same as fixing \(x_{or} = 0\). Because each order is picked alone, capacity is checked per order, not as a sum of orders on the picker.

\[ (o,r) \in E \iff \begin{cases} \text{the order names no equipment, or it matches picker } r \\ W_o \le W_r^{\max} \\ V_o \le V_r^{\max} \text{ when both volumes are present} \end{cases} \]

If \(E\) contains no picker for order \(o\), then \(y_o\) is forced to \(0\). The result tags that order no_eligible_picker. An order that is eligible but left at \(y_o = 0\) is tagged shift_time_limit_or_priority_tradeoff. --withhold-if-late-at-start (default off) removes a job before the solve when its duration exceeds the window every eligible picker still has before the cutoff. That reason is cannot_meet_cutoff. The window is \(A_r(D_o) = \min(\max(0, D_o - s_r), S_r)\). Jobs removed here are not forced on by --require-must-ship.

Assignment MILP

Same model in Gurobi (assignment_solver="gurobi") and in HiGHS ("highs", the default). HiGHS minimizes, so its coefficient vector is the negative of the Gurobi maximization. The reported objective is the maximization value.

Variables

\[ y_o \in \{0,1\} \quad \forall o \in O \]
\[ x_{or} \in \{0,1\} \quad \forall (o,r) \in E \]
\[ \omega_r \ge 0, \qquad u_r \ge 0 \quad \forall r \in R \]

Objective

\[ \max_{y,x,\omega,u} \sum_{o \in O} w_o\, y_o - \beta \sum_{r \in R} u_r \]

HiGHS solves the equivalent minimization

\[ \min -\sum_{o \in O} w_o\, y_o + \beta \sum_{r \in R} u_r \]

and returns the negation of that optimal value, so both solvers report the same score. With the default \(\beta = 0\) the imbalance variables stay in the model and drop out of the score. The command-line flag --share-shift sets \(\beta = 0.001\). One ordinary order, weight \(1\), is worth \(1000\) minutes of unevenness, so an order that still fits is not dropped to even the shift. Setting every \(w_o = 1\) makes the score a count of released orders.

Two optional penalties use the same units as \(w_o\). Both default to \(0\). \(J\) is the set of pairs where the job is eligible for a pallet jack and the picker is a forklift.

\[ \max \sum_{o \in O} w_o\, y_o - \beta \sum_{r \in R} u_r - \lambda \sum_{o \in O} \pi_o L_o - \gamma \sum_{(o,r) \in J} x_{or} \]

\(\lambda\) is --lateness-weight. \(\gamma\) is --prefer-jack. Finish times follow earliest-deadline order on each picker, starting at minute \(0\). Undated jobs go last and are not late. \(D_o\) is minutes from that start. The release weight, including the flat \(100000\), stays in the first sum. On this weighted sum, keep \(\gamma\) below the smallest job weight so a tie moves toward a jack and the job stays released. Under --staged-assignment any positive \(\gamma\) minimises the count of pairs in \(J\) with coefficient \(1\).

Finish time and lateness, present when \(\lambda > 0\) on this weighted solve, and on the lateness stage below.

\[ C_o \ge \sum_{o' \preceq o} \tau_{o'}\, x_{o'r} - M(1 - x_{or}) \qquad \forall (o,r) \in E \]
\[ L_o \ge C_o - D_o - M^{\mathrm{late}}(1 - y_o), \qquad L_o \ge 0 \]

The sum is the durations of order \(o\) and of the jobs that deadline order places before it on picker \(r\). \(M\) is the longest shift. \(M^{\mathrm{late}} = M + \max(0, -\min D)\). HiGHS writes the finish row as \(C_o - \text{prefix} - M x_{or} \ge -M\). Dropped jobs are not charged lateness.

One picker, shift \(10\). Order BIG has \(\tau = 9\), \(w = 5\). Orders SMALL1 and SMALL2 have \(\tau = 4\), \(w = 1\) each. BIG alone scores \(5\). The two small orders together use \(8 \le 10\) and score \(2\). The weighted solve releases BIG. Benchmark mode sets every weight to \(1\) and releases the two small orders, score \(2\).

Constraints

One picker if the order is released. An unreleased order has every \(x_{or} = 0\).

\[ \sum_{r:\,(o,r)\in E} x_{or} = y_o \qquad \forall o \in O \]

Workload is the sum of assigned route durations.

\[ \omega_r = \sum_{o:\,(o,r)\in E} \tau_o\, x_{or} \qquad \forall r \in R \]

Shift limit.

\[ \omega_r \le S_r \qquad \forall r \in R \]

Imbalance is the absolute deviation from the mean workload. It is a soft term through \(\beta\), not a hard cap.

\[ \bar\omega = \frac{1}{|R|} \sum_{q \in R} \omega_q \]
\[ u_r \ge \omega_r - \bar\omega, \qquad u_r \ge \bar\omega - \omega_r \qquad \forall r \in R \]

Together those two inequalities are \(u_r \ge |\omega_r - \bar\omega|\). With \(\beta \gt 0\) the objective pushes each \(u_r\) down to that absolute gap. \(y = 0\), \(x = 0\), \(\omega = 0\), \(u = 0\) satisfies every row, with objective \(0\).

Gurobi writes the mean as a linear expression inside the two imbalance rows. HiGHS writes the same rows with share \(1/|R|\) on every workload column. Both are the pair of inequalities above.

Staged release

--staged-assignment is off by default. The weighted sum above stays the live objective. The flag replaces that one sum with five stages. Each stage locks the objective value it reached, with tolerance \(10^{-6}\), so a later stage may swap jobs of equal value. The lock uses that incumbent. The public score is still the release-weight sum of the jobs that remain.

  1. Maximise the count of must-ship jobs. The absolute stop is \(0.5\). The stage is skipped when the wave has none.
  2. Maximise \(\sum w_o y_o\) over the other jobs. Must-ship weights stay out of this sum, so equal \(100000\) jobs can still swap under the count lock. When the work exceeds the shift, weights decide which ordinary jobs stay out.
  3. Minimise \(\sum \pi_o L_o\) on the released set, including when \(\lambda = 0\). No deadlines makes this stage a no-op.
  4. Minimise \(\sum u_r\), only when \(\beta > 0\).
  5. Minimise the count of pairs in \(J\), only when \(\gamma > 0\). The coefficient is \(1\), so the flag tie-breaks after release.

A stage that hits the time limit keeps its incumbent, and the next lock can sit short of the true maximum. --require-must-ship is a separate constraint \(y_o = 1\) on every must-ship job. It is not this staged mode. When those jobs cannot all fit, is_optimal is false, infeasible_must_ship is true, and status_reason is required_must_ship_jobs_cannot_all_fit. The printed line is “Required must-ship jobs cannot all fit.” A plan that releases nothing without that flag stays feasible. Staged assignment leaves a must-ship job out when it does not fit and still returns a plan.

One picker, shift \(100\). J1 has cutoff \(10\), duration \(8\), weight \(2\). J2 has cutoff \(12\), duration \(8\), weight \(2\). With \(\lambda = 1\), both jobs score \(0\) once lateness is charged, and one job scores \(2\). The weighted path releases one job. The staged path releases both and reports \(4\) late minutes. The public score is \(4\).
On the 16-truck wave, lateness weight \(1\) and a \(60\) second stage limit, --prefer-jack 0.1 only turns on stage 5. PACK_A stayed \(84\) of \(84\), score \(400424.4\). PACK_B stayed \(87\) of \(87\), score \(700414\). Late minutes stayed \(0\). The jack count proved at \(0\). Twelve forklift-only jobs stayed on forklifts. Each dock stayed inside \(480\) minutes. Across both docks PJ04 is \(506.5\) and PJ08 is \(504.7\), so the minute sum raises. Reports are outputs/chunk_assign/gap_wave/staged_prefer_jack/. The default stays \(\gamma = 0\).

Stopping gap

The stop is an absolute tolerance of a tenth of the smallest positive weight, raised above solver noise when that still sits below half a job. A caller mip_gap is stored as gap_requested and does not loosen the solve.

\[ w_{\min} = \min \{ w_o : w_o > 0 \} \qquad \text{target} = 0.1\, w_{\min} \qquad \text{noise} = 10^{-6}\, U \]
\[ \text{absolute} = \begin{cases} \text{target} & \text{if noise} \ge w_{\min} \\ \min\bigl(\max(\text{target},\, 10 \cdot \text{noise}),\, 0.5\, w_{\min}\bigr) & \text{otherwise} \end{cases} \]

\(U\) is an upper bound on the objective. The sum of the absolute coefficients is not that bound once lateness or imbalance is continuous. On the weighted objective, \(U\) is the sum of the positive release weights, plus \(|\beta|\) times twice the shift lengths, plus \(|\lambda|\) times \(\sum \pi_o M^{\mathrm{late}}\) over dated jobs, plus \(|\gamma|\) times the number of pairs in \(J\). Twice the shift lengths bounds the sum of absolute deviations from the mean. The ordinary stage uses only the ordinary weights, so a \(100000\) coefficient is outside that stage’s scale. The must-ship count stage stops at an absolute gap of \(0.5\). The jack stage uses the smaller of \(0.5\) and the weight tolerance.

SciPy’s MILP wrapper accepts mip_rel_gap only, so HiGHS is given mip_rel_gap = absolute / max(U, 1). Gurobi is given MIPGap = 0 and MIPGapAbs equal to the absolute tolerance, because Gurobi stops when either gap is met. Each solve records stop: time_limit when the limit hit, no_solution when no usable plan was returned, proven when the achieved absolute gap is within \(10^{-6}\) or within \(1\%\) of the target, and gap_reached otherwise. A staged result uses time_limit if any stage hit the limit, and otherwise the last stage’s stop. The weighted path discards a solve that is not usable. A staged plan keeps a time-limit incumbent.

On 2026-10-21 the 16-truck wave was solved again with \(\lambda = 1\) and a \(60\) second limit on each stage. Two docks

Each picker call takes one depot_id and sees every picker in the file. python source/run_docks.py solves each depot folder, writes that dock’s utilisation from shift_duration, then sums busy minutes and compares the sum with that shift. A picker more than \(0.0001\) minute past the shift raises. The 2026-10-21 prefer-jack plan is that case: PJ04 at \(506.5\) minutes and PJ08 at \(504.7\), against \(480\). A pass is the minute total. Clock overlap, and the \(1.1\)-minute walk between docks \(72\) m apart at speed \(65\), stay outside the screen. The check does not rebuild the assignment. Files that were already written can be checked with python source/assignment_reports.py and one utilisation.csv per dock. 

python source/run_docks.py --by-depot outputs/chunk_model/by_depot --pickers inputs/layout_warehouse/pickers.csv --travel inputs/layout_warehouse/travel_times.csv --out outputs/chunk_assign/docks --lateness-weight 1 --time-limit 60

Add --staged-assignment for the five-stage release. The single-dock optimizer is still python source/order_picking_optimizer.py with one --depot.

Outside this model

  • Pallet ids, cases, stack height, trailer pads, axle weight, and the LoadMax fill score. Those stay in the truck model.
  • Choosing the depot inside phase 1 or phase 2, and splitting one order across depots.
  • Batching several orders into one walk, zone picking, and a second location for the same item.
  • A \(z\) edge or a separate stop for the left and right rack. Upper levels and awkward slots are \(r_j\).
  • Item handling inside \(T_{ij}\). That handling is \(p_o\).
  • A ranking that clears every higher weight before any lower weight. --staged-assignment is must-ship count, then the other jobs by weight, then lateness. The default remains one weighted sum, and must-ship stays the finite weight \(10^{5}\) inside that sum.
  • One model that assigns both docks together, a loading sequence, a cap on pallets waiting at the dock, aisle congestion, a stock check, and a mid-shift re-plan. run_docks.py sums busy minutes after the two solves. A pass is that total.

How to visualize

Static PNGs from order_picking/visualizer/plot_picking.py. They draw a solved route, every picker’s routes on the warehouse floor, and a solved shift. They do not change the optimizer.

matplotlib is listed in the repo requirements.txt for these pictures. Install it with the rest of the project, from the repo root: 

pip install -r requirements.txt

Run the commands from order_picking/. inputs/layout_example/ is the six-aisle warehouse. inputs/layout_small/ is the two-aisle picture used in the worked numbers. Saved assignments and PNG exports are under outputs/. The two browser pages are visualizer/warehouse.html and visualizer/assignment.html.

One order’s walk

Gray lines are the aisle and cross-aisle centrelines. Arrows are the shortest directed walk between consecutive stops. A marker is a stop. --route is the visit order from Phase 1, depot first and last.

The two-aisle command puts the depot at \((0, 0)\), which is already on aisle A1. DEPOT → L1 is the segment from \((0, 0)\) to \((0, 3)\). Its length is 3, and the matrix cell is 3. The closed walk \(3 + 13 + 10 = 26\) uses that same on-centre depot. A depot that sits off the centreline is a separate first segment, from the depot point onto the aisle, and then the centreline walk. Those lengths add up to the matrix time when speed is 1 and retrieval is 0. On this map a depot at \((-1, 0)\) makes DEPOT → L1 length \(1 + 3 = 4\), and the matrix cell is 4. An earlier check that reported 6 used a different map: the slot was at \(y = 5\), so the offset plus the aisle was \(1 + 5 = 6\). The warehouse depot is \((0, -2)\), two units in front of A1. That offset is in inputs/layout_example/depots.csv and in travel_times.csv. A3 runs up only. L-A3-01 to L-A3-04 is 18. The return is 50, up to the back cross-aisle and down a two-way aisle. Retrieval time and line pick_time are minutes at the stop. They are not drawn. A step with no walk is a dashed red line labeled “no walk”, and the picture still finishes. A depot name in the middle of the route is named under the picture. That walk is drawn. It is not a second depot chosen by Phase 1.

The shift

One row per picker. The gray bar is shift_duration. Colored bars are the assigned orders, packed from time zero in the row order of the assignments file. That order is assumed so the picture has a left-to-right sequence. Phase 2 does not choose it, and the chart title says so. The empty part of the gray bar is idle time. Names after --left-out are printed under the chart.

The warehouse shift is inputs/layout_example/pickers.csv. P1 and P2 are pallet jacks at 2500 kg and volume 2.0. P3 is a forklift at 5000 kg and volume 4.0. Each shift is 480 minutes. O4 is 3200 kg and volume 3.2 and names a forklift, so it stays on P3. A jack cannot take that order even when the equipment cell is blank. outputs/layout_example/assignments.csv is the default solve, balance weight 0: O1, O2, O3, O5, and O6 on P1 (433 minutes) and P2 idle, score 100006. outputs/layout_example/assignments_shared.csv is --share-shift, balance weight 0.001: P1 has O3 (98.5 minutes), P2 has O2 and O5 (194), and P3 has O1, O4, and O6 (212.5). The score stays 100006. The forklift also takes light orders when required_equipment is blank. A fresh solve at balance weight 0 can split the pallet-jack orders across P1 and P2 and still score 100006. Blank equipment cells in orders.csv are no equipment requirement.

From Python

Run this from order_picking/ with source and visualizer on PYTHONPATH. The command-line scripts add those folders themselves. solve_order_picking fills result. routes[order_id]["route"] is the visit list. The same command-line entry point is python source/order_picking_optimizer.py with those CSV paths and --depot DEPOT. --assignments-out writes the Gantt CSV from picker_assignments. The drawn walk comes from route_legs. A leg with no polyline is the dashed red “no walk” segment. route_walks is the same geometry and raises when any leg has no polyline. 

import pandas as pd
from order_picking_optimizer import solve_order_picking
from plot_picking import plot_order_route, plot_picker_routes, plot_shift_gantt

orders = pd.read_csv("inputs/layout_example/orders.csv")
items = pd.read_csv("inputs/layout_example/order_items.csv")
pickers = pd.read_csv("inputs/layout_example/pickers.csv")
travel = pd.read_csv("inputs/layout_example/travel_times.csv")
aisles = pd.read_csv("inputs/layout_example/aisles.csv")
cross_aisles = pd.read_csv("inputs/layout_example/cross_aisles.csv")
locations = pd.read_csv("inputs/layout_example/locations.csv")

result = solve_order_picking(orders, items, pickers, travel, depot_id="DEPOT")
plot_order_route(
    aisles, cross_aisles, locations, result["routes"]["O1"]["route"],
    depot_id="DEPOT", depot_x=0, depot_y=-2, out="route.png",
)
plot_picker_routes(
    aisles, cross_aisles, locations, result,
    depot_id="DEPOT", depot_x=0, depot_y=-2, pickers=pickers, out="floor.png",
)
plot_shift_gantt(result, pickers, out="gantt.png")
