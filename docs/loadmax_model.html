LoadMax math model — slots, not Tetris

The live solver is a mixed-integer program: assign already-built 40″×48″ pallets to numbered floor pads and layers. This page walks the A-B truck instance — inputs, variables, objective, every constraint with a picture, then the output tables. Floor-map variants (20 / 21 / 22) are in truck_pallet_layouts.html. The extra 1D lot model (length from palletLengthDict, not numbered pads) is loadmax_mixed_length.html.

What is being decided

For each pallet and each empty pad, the model answers: which truck, which layer (1 or 2), which numbered pad. It does not choose pallet rotation, does not place cartons in continuous \(x,y,z\), and does not build pallets from cases.

DecisionBinary \(y_{v,l,p,i}\) — pallet \(i\) on truck \(v\), layer \(l\), pad \(p\)
Not a decision40″×48″ footprint, pinwheel vs straight (that is the Config map)
EngineHiGHS MIP via scipy.optimize.milp (maximise, implemented as minimise of the negated objective)
A-B size6 trucks × 2 layers × 30 pads × ~33 pallet types ≈ 12k assignment binaries

Toy. Pad 7, truck 1, layer 1 can hold at most one of plt_12 or plt_208 (or nothing). Layer 2 on the same pad 7 is a second slot in that column, not a different floor location.

Decision variables

\[ y^{\text{full}}_{v,l,p,i} \in \{0,1\}, \quad y^{\text{prtl}}_{v,l,p,j} \in \{0,1\} \]

Pallet \(i\) (full) or \(j\) (partial) assigned to truck \(v\), layer \(l\), pad \(p\).

\[ F_{v,l,p} = \sum_i y^{\text{full}}_{v,l,p,i}, \qquad P_{v,l,p} = \sum_j y^{\text{prtl}}_{v,l,p,j} \]

Indicators: this spot holds a full / a partial.

\[ w_{v,l,p} = \sum_i \omega_i\, y^{\text{full}}_{v,l,p,i} + \sum_j \omega_j\, y^{\text{prtl}}_{v,l,p,j} \] \[ h_{v,p} = \sum_{l,i} h_i\, y^{\text{full}}_{v,l,p,i} + \sum_{l,j} h_j\, y^{\text{prtl}}_{v,l,p,j} \]

Weight on that layer of the column, and total stack height of the column.

Also: material counts \(m_{v,s}\), “SKU present” binaries, \(y^{\text{prior}}\) bonuses, and (ocean only) milk-run terms.

Objective — load important SKUs on the first trucks

Maximise a fill score. HiGHS minimises, so the code stores the negated coefficients. Live Pyomo 4-term fill:

\[ \begin{aligned} \max \quad &\sum_{v,l,p,i} c_v \cdot \pi_i \cdot y^{\text{full}}_{v,l,p,i} + \sum_{v,l,p,j} c_v \cdot \pi_j \cdot f_j \cdot y^{\text{prtl}}_{v,l,p,j} \\ &+ \sum_i \rho\, y^{\text{prior,full}}_i + \sum_j \rho\, y^{\text{prior,prtl}}_j - \lambda \cdot E \end{aligned} \]
SymbolA-BMeaning
\(c_v\)800…300container_priority[v] — truck 1 is worth most
\(\pi_i\)2 if SKU is in skuPriorityIncentive, else 1priorityIncentive multiplier
\(f_j\)e.g. leftover/casesPartial counts as a fraction of a full
\(\rho\)2Same incentive on the extra \(y^{\text{prior}}\) term
\(E\)≥ 0How many SKUs over unique_sku_n = 31
\(\lambda\)1 × 3 = 3sku_penalty × sku_penalty_factor

Worked scores — put one pallet on a truck

A listed SKU on truck 1 scores \(800 \times 2 = 1600\). The same pallet on truck 6 scores \(300 \times 2 = 600\). That is why priority freight lands on the first trucks — not because of palletProfitDict.

The older fill (no extra ×2 for listed SKUs) is commented in _build_objective, not deleted. Milk-run (position × priority³) is built only when ocean mode is on; A-B trucks do not use it. The integer rank 1/2/3/5 in skuPriorityIncentive is unused on the truck fill — only membership matters.

When Class R is active, the same objective subtracts a penalty for opening the class and, when the mix weight is positive, for mixing it with Class T. HiGHS minimises, so those coefficients are stored positive.

\[ \lambda_R = w_R \cdot c_{\min} \cdot f_R \qquad \mu = w_{\mathrm{mix}} \cdot c_{\min} \cdot f_R \]

\(c_{\min}\) is the smallest explicit container_priority. \(f_R\) is the smallest Class R partial fraction, or \(1\) when no Class R pallet is partial. A partial that is not Class R does not change \(f_R\). Defaults are \(w_R = 0.5\) and \(w_{\mathrm{mix}} = 0.25\). Priorities 800 and 300 with no Class R partial give \(\lambda_R = 150\) and \(\mu = 75\). A fraction \(0.3\) on a Class R partial gives \(45\) and \(22.5\). A very small Class R fraction makes consolidation weak. reducedCapConsolidationWeight is that knob, and the default stays \(0.5\). A weight above \(1\) can leave a Class R pallet off, because demand is at most once.

An unset container 0 still loads at priority \(0.5\) and is left out of \(c_{\min}\), so it does not shrink the penalty on the other trucks. That truck pays \(\min(\lambda_R,\, w_R \cdot 0.5 \cdot f_R)\) for opening Class R, and the same idea for the mix penalty, so a Class R pallet can still land there. An explicit priority, including an explicit \(0.5\), stays in \(c_{\min}\). A direct inputParams dict follows the same rule as a CSV read. A-B trucks are numbered \(1\ldots 6\) and have no class keys, so both penalties are \(0\).

Constraints

Each block is one family of rows in the HiGHS matrix. Examples use A-B pads and the HiGHS load where it helps.

1. Total cargo weight

\[ \sum_{l,p} w_{v,l,p} \le W_v^{\max} \quad \forall v \]

On A-B, \(W_v^{\max}\) is 42,000 lb for every truck. A set containerMaxWt replaces that number on the trucks it names.

Truck 1 loaded 41,936 lb (99.8% of cap). One more ~1,200 lb pallet on that truck is infeasible even if a pad is free.

2. Each physical pallet used at most once

\[ \sum_{v,l,p} y^{\text{full}}_{v,l,p,i} \le d_i \qquad \sum_{v,l,p} y^{\text{prtl}}_{v,l,p,j} \le d_j \]
plt_178 has demand 20. The solver may leave some on the dock (≤, not =). Ocean historically used equality; trucks use ≤ so leftover pallets are allowed when weight/axles bind.

3. At most one pallet per spot

\[ F_{v,l,p} + P_{v,l,p} \le 1 \]

A “spot” is the triple (truck, layer, pad). Two pallets can share a pad only by stacking: layer 1 and layer 2 of pad 8.

4. Compact packing (no holes from the seed)

On when enforce_compact_packing is Yes. Seed \(p^\star = 12\). Occupancy \(O_{v,l,p} = F+P\).

\[ \begin{aligned} p &< p^\star &&\Rightarrow& O_{v,l,p} &\le O_{v,l,p+1} \\ p &> p^\star &&\Rightarrow& O_{v,l,p} &\le O_{v,l,p-1} \\ p &\le p^\star,\ p\text{ even} &&\Rightarrow& O_{v,l,p} &= O_{v,l,p-1} \end{aligned} \] Layer 2 at the seed only after layer 1 at both ends is used: \[ O_{v,2,12} \le O_{v,1,1}, \qquad O_{v,2,12} \le O_{v,1,30} \]

In words: fill from pad 12 toward the nose and toward the door; pair left/right in the front half; do not start a second layer at 12 until pads 1 and 30 on layer 1 are occupied.

6. Stack height, with a shorter door

\[ h_{v,p} \le \begin{cases} 3.5 & p \in \{29,30\} \\ 9 & \text{otherwise} \end{cases} \quad\text{(ft, A-B)} \]

Typical pallet ~3.8 ft, so door pads are single-layer. Body pads fit two (~7.6 < 9). Volume % in the UI uses the same door exception in the denominator:

\[ \text{volume \%} = \frac{\sum_p h_{v,p}}{9\cdot(30-2) + 2\cdot 3.5} = \frac{\sum_p h_{v,p}}{259} \]
Truck 1 reported 65.3% volume. Using \(30\times 9 = 270\) would understate cube by about 4 points — that was the screenshot mismatch, not pallet L×W.

7. Crushing — heavier below

\[ w_{v,l,p} \ge \sum_{s>l} w_{v,s,p} \]

On two layers this is “layer 1 at least as heavy as layer 2.”

legal

8. Left / right balance

front_to_back_tolerance = 0 on A-B, so the front/back pair is not added (the code only inserts those rows when the tolerance is positive). Side-to-side is on at 10%:

\[ (1-0.1)\, W^{\text{right}}_v \le W^{\text{left}}_v \le (1+0.1)\, W^{\text{right}}_v \]

Left = odd pads, right = even pads. Click “Left” / “Right” on the map above. This is cargo left vs right, not a physics roll moment.

9. Front / rear cargo (the MIP “axles”)

Not a geometric fifth-wheel calculation. Each pad has coefficients in positionGroupBalanceCoefficientDict:

\[ \begin{aligned} \text{front}_v &= \sum_{l,p} (A_{p}+C_{p})\, w_{v,l,p} \le 19920 \\ \text{rear}_v &= \sum_{l,p} (B_{p}+D_{p})\, w_{v,l,p} \le 22080 \end{aligned} \]

Pads 1–12: coefficient 1 on A or C. Pads 15–30: 1 on B or D. Pads 13 and 14 are 0.5 / 0.5, so they count on both axles and front+rear still equals total cargo.

HiGHS A-B cargo vs the 19,920 / 22,080 caps. All six trucks sit just under both.

Truck 1: front 19,874 (46 lb under) + rear 22,062. The MIP treats a 1,190 lb pallet on pad 1 the same as on pad 12. Physically pad 1 is much closer to the fifth wheel — see the optional check at the end.

10. SKU-count tracking and penalty

\[ m_{v,s} = \text{how many pallets of SKU }s\text{ on truck }v \] \[ u_{v,s} \ge m_{v,s} / (2\cdot 30), \quad u_{v,s}\in\{0,1\} \] \[ E \ge \sum_v \sum_s u_{v,s} - 31 \]

\(E\) is penalised in the objective. A-B has 31 materials and unique_sku_n = 31, so spreading SKUs across extra trucks is slightly discouraged. It does not forbid a SKU.

11. Priority bonus cannot exceed assignments

\[ 0 \le y^{\text{prior,full}}_i \le \min\Big(d^{\text{prior}}_i,\ \sum_{v,l,p} y^{\text{full}}_{v,l,p,i}\Big) \]

Excel YES / Balance Pallets writes max_prior_*. The bonus term \(\rho y^{\text{prior}}\) only pays for pallets that were actually loaded, and only up to that cap. Equality was wrong: with max_prior = 0 it would have forced every assignment to 0.

12. VDR stacking groups G2 / G3 / G4

Warehouse classes. The HiGHS A-B CLI leaves these off (vdr_stacking_rules=False). They exist in the model for other markets.

13. Optional class caps

Built only when a class key is present. A-B has no class keys, so these rows are absent and the no-keys model is unchanged.

\(I^R_v = 1\) when truck \(v\) holds any Class R pallet. Each Class R assignment forces the indicator on, and the sum of those assignments keeps it off when the truck has none. One summed big-M row is not used. \(\bar n_v = \min(n_v, \mathrm{cap}_R)\). A truck whose nominal pad count is below the class cap keeps that nominal count. The same pattern applies to Class T.

\[ y \le I^R_v \quad\text{for each Class R assignment } y \qquad \sum y \ge I^R_v \]
\[ \sum_{l,p}(F_{v,l,p} + P_{v,l,p}) \le n_v - (n_v - \bar n_v)\, I^R_v \]

Soft mode only charges the penalty. Hard mode also limits how many trucks may open Class R. The limit fills the largest \(\bar n_v\) first until Class R demand is covered. When every truck can hold the class cap and the fleet is large enough, that count is \(\lceil D_R / \mathrm{cap}_R \rceil\). A cap above every truck’s nominal raises on read.

\[ \sum_v I^R_v \le L \qquad\text{hard mode only} \]
\[ M_v \ge I^R_v + I^T_v - 1 \]
Four trucks with nominal caps 3, 3, 3, and 8, class cap 6, and Class R demand 10. Applicable caps are 3, 3, 3, and 6. Largest first, 6 + 3 + 3 covers 10, so hard mode allows 3 trucks. \(\lceil 10/6 \rceil = 2\) would be too small, because 6 + 3 = 9.

Optional post-solve physics check (not a constraint)

After the MIP, each used pad can be mapped to a bay center \(X\) (15 bays × 40″ along the trailer) and cargo can be split with a kingpin / rear-tandem lever. That is not in the MIP. On this A-B load the shortcut is close: trucks 2–6 within ~2%; truck 1 about 1,560 lb more on the kingpin than A+C reports, because 2-high weight sat on bays 4–6 (true nose-middle) while pads 1 and 12 still count equally as “front.”
